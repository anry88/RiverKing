# Правила создания ивентов

## Даты и часовой пояс

Для всех новых ивентов начало и окончание задаются в **00:00:00 UTC указанных дат**. Это то же правило, которое использует Android-админка при вводе даты без времени.

- В JSON используйте явную UTC-зону: `YYYY-MM-DDT00:00:00Z`.
- В admin API передавайте соответствующие epoch milliseconds в `startTime` и `endTime`. Часовой пояс Windows, контейнера или телефона не добавляется к этим значениям.
- Для месячного ивента начало — первое число месяца, окончание — первое число следующего месяца; обе границы в 00:00 UTC.
- Местное время приводите только для отображения, через именованную зону `Europe/Belgrade`. В Белграде полночь UTC соответствует **02:00 летом** и **01:00 зимой**. Не фиксируйте одно местное время для всех месяцев.
- Не выводите расписание из текстовых дат старых SQLite-копий, SQL-выгрузок без часового пояса или исторического пула рыб. Они могут содержать прежнее локальное время. Расписание определяется этим правилом, а исходные пулы используются для состава и баланса.

Пример для ноября 2026:

```json
{
  "start": "2026-11-01T00:00:00Z",
  "end": "2026-12-01T00:00:00Z"
}
```

По Белграду это **1 ноября 2026 01:00 — 1 декабря 2026 01:00**.

## Создание и проверка

1. Подготовьте отдельный каталог `docs/events/YYYY-MM-topic/` с `event.json`, составом, весами, наградами и утверждёнными изображениями. Сначала опубликуйте необходимый контент через обычный `develop → main` PR.
2. Передайте `ADMIN_API_TOKEN` через окружение и выполните проверку без записи:

   ```bash
   python3 scripts/configure-event.py docs/events/YYYY-MM-topic/event.json --base-url https://riverking.tg-games.com
   ```

3. Проверьте UTC-даты, пересечения с другими ивентами, каталог, изображения и награды. Импорт отклоняет даты без часового пояса, не в UTC или не в полночь до обращения к API.
4. Повторите команду с `--apply`. После создания скрипт перечитывает сохранённую запись и сверяет настройки; повторный запуск не создаёт дубликат.
5. Зафиксируйте ID и сохранённые UTC-даты, а в сообщении пользователю переведите обе границы в его часовой пояс с учётом сезонного смещения.

Для исправления уже созданного будущего ивента обновляйте **ту же запись** через админку или `PUT /api/admin/events/{id}`. Перед изменением сохраните её настройки, убедитесь, что ивент ещё не начался и новые даты не пересекаются с другими событиями. После изменения перечитайте запись и сверьте даты, состав, веса и награды. Скрипт создания намеренно не перезаписывает отличающуюся конфигурацию. Изменение расписания в базе не требует сборки или перезапуска сервера.
